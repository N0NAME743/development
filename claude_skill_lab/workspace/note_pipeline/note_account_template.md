# noteアカウント作成テンプレート（YAKUMOの電脳観測ノート版）

コンセプト：YAKUMO（電脳妖精）が人間観察のついでに見つけた「人間のちょっとした詰みパターン」を、
先生ぶらず・とぼけながら記録していくノート。相談に「答える」のではなく、
たまたま観測して面白かったことを興味本位で教えてくれる立ち位置。

※これはCharacter Bible公式設定のX運用（`YAKUMO X Prompt v1.4.md`）を上書きするものではなく、
　note用の派生企画（Concept/Candidate扱い）です。正式Canon化する場合は別途検討してください。

---

## 0. 最終方針（2026-09-09 決定事項）

複数回の壁打ちを経て、以下で方向性を確定：

- **コンセプト**: 「YAKUMOなりに、悩みへ答える」。ただし先生ポジションは取らない。
  「相談に答える」ではなく「観測してて気づいたら、実用的な中身まで持って帰ってきた」の体を貫く。
  → §5「記事タイトルの型」・記事本文のトーンは前セクションのまま維持（変更なし）。
- **理由**: note収益化の実地調査で「日記のような軽い内容は単発有料では売れにくい／
  具体的なノウハウ・実例があるものは売れる」という傾向が判明。YAKUMOの声を保ったまま
  中身の実用性を落とさない、というのがこの型の存在意義。
- **テーマの集め方**: **ハイブリッド**。
  - 当面（フォロワーがまだいない開始期）：これまで通りClaudeが普遍的な悩みテーマを
    提案し、YAKUMOの声で記事化（提案型）
  - フォロワーがついてきたら：読者から悩みを募集し、YAKUMOが答える回を混ぜる（双方向型）
  - 双方向型は「受付・選別」という運用コストが発生するため、最初から両方同時にはやらない。
    提案型で軌道に乗ってから段階的に混ぜるのが現実的。
- **収益モデル**: 単発500円記事（実用性で売る）を基本としつつ、将来的に
  note「定期購読マガジン」でファン化を狙う拡張余地も残す（§9で詳述）。
  最初から両方は作り込まず、まず単発記事で反応を見る。

## 4. マガジン構成（カテゴリ整理）

「〜の整え方」「〜のヒント」のような教科書的な名前を避け、観測ログっぽい名前に：

1. 人間観察：人間関係編

3. 人間観察：お金編
4. 人間観察：暮らし編
5. 人間観察：自己理解編

→ 名前を統一フォーマット「人間観察：〇〇編」にすることで、
　「同じヤクモが書いてる」感を保ちつつカテゴリ分けする。

## 5. 記事タイトルの型（統一フォーマット）

先生口調の型は使わない。YAKUMOが独り言で気づいた体のタイトルに揃える：

- 「〇〇な人間、だいたい△△する」
- 「〇〇、観測してて気づいたこと」
- 「〇〇な人間が、実は△△だった話」

（例：今回の下書き「『休日、絶対有意義に過ごすぞ』からの、だいたい詰むやつ」は型1）

X Prompt §32「AI臭を避ける」の禁止表現（〜ですね／〜してみてはいかがでしょうか等）は
タイトル・本文とも厳禁。

## 6. 価格設定の初期方針

- 基本 **500円固定**（2本目以降）
- **1本目のみ完全無料で公開**（2026-09-09決定）。狙いはキャラとトーンを知ってもらうこと優先、
  読者ゼロの状態でいきなり有料は反応が読めないため。有料化は2本目から。
- 2本目以降は、冒頭は無料公開、続きから有料（分量は内容次第。YAKUMOは「情報提供が必要な投稿は
  長くしてよい」というルールがあるので、文字数で厳密に区切らず「観測の面白さが伝わった直後」で区切る）
  - 参考区切り位置の例（`note_draft_yakumo_mony_holiday.md`基準）：
    「面白くない？」まで無料、「じゃあ実際どうすんの、って話。」以降を有料にする案
- 記事末尾は「まとめ」で締めない。CHECK 10（毎回オチを付けようとしていないか）に従い、
  彼女らしい素っ気ない締め（「今度また観測しといてあげる」等）にする

### 区切り位置の表記ルール（2026-09-09追加）

記事本文には読みやすさのための場面転換用「---」を複数箇所に入れるが、これは
有料/無料の区切りとは無関係。**有料化する記事では、区切り候補の位置にだけ
`<!-- PAYWALL -->` というHTMLコメントを追加で入れる**（「---」と紛らわしいので分離）。

運用手順：
1. 下書き段階で`<!-- PAYWALL -->`を区切り候補位置に入れておく
2. note.comのエディタにコピペする際、そのコメントの位置で実際に
   「ここから先は有料」機能（note標準機能、UI操作）を設定する
3. `<!-- PAYWALL -->`というテキスト自体はnote側の機能ではなく、単なる下書き用の目印なので、
   実際の記事本文からは削除してから公開する（コメントのまま公開しない）

## 8. 告知X投稿の運用ルール（重要な注意）

既存の`yakumo-social-agent`パイプライン（Day One → YAKUMO変換 → Discord承認 → X投稿）は
**あくまでYAKUMO本人のXアカウント運用のため**に設計されています。

note告知を同じYAKUMOアカウントから流す場合、既存のContent PolicyやDry Runの仕組みと
整合させる必要があるため、以下は分けて検討してください：

- 同じYAKUMOアカウントから告知するか、noteリンク投稿だけ別枠にするか
- 既存パイプラインのDiscord承認フローにnote告知も乗せるか、手動で予約投稿するか

（この設計判断は本テンプレートの範囲外。yakumo-social-agent側の実装と合わせて別途検討推奨）

## 9. 将来の拡張余地：定期購読マガジン（今回は着手しない）

単発記事が軌道に乗ってきたら検討する選択肢として記録しておく：

- 無料〜低頻度の短いつぶやき観察を「マガジン」に流し、ファン化（パラソーシャル関係）の

- 狙いは「日記の軽さ」を弱みではなく強みに変えること（単発では売れにくいが、
  継続接触前提のメンバーシップでは強みになるというnote実地調査の結果に基づく）

**今回はまだ着手しない**。まず単発記事を2〜3本出して反応を見てから判断する。

## 10. 双方向型（読者からの悩み募集）を混ぜるタイミング

- 発動条件の目安：フォロワー・スキが一定数つく、またはコメントで悩みが自然に集まり始めたら
- 運用: 募集告知投稿 → 集まった悩みから普遍性のあるものを選別 → YAKUMOの声で記事化
- 選別基準は§0と同じ「1年後も検索され続けるか」「競合が薄いか」を踏襲
- 個人が特定できる情報は記事化前に匿名化・一般化する（実在の相談者だと分からない形にする）

## セットアップの実際の手順（note.com上でやること）

1. note.comでアカウント作成
2. 上記2・3をプロフィール欄・アイコンに設定
3. マガジンを5つ作成（4）

7. 告知の出し方は8の注意点を踏まえて別途決定
