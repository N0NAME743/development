
# YAKUMO New Default Costume — Final Candidate Specification v0.9

> 本書は、少女YAKUMOの新Default Costume候補について、現在までのVariation / Refine Testで選定された衣装構造を固定し、最終評価するためのCandidate仕様書である。  
>   
> 本仕様は**Official Costumeではない**。  
> 現行Official Default Costume `C01-B Cyber Pleats Style / Standard Form` を現時点では置換しない。

## 1｜Candidate Identity

| 項目 | 定義 |
|---|---|
| Working Name | **New Default Costume — Final Candidate** |
| Version | **v0.9** |
| Status | **Final Candidate / Not Official** |
| Character | YAKUMO |
| Form | 少女YAKUMO / Standard Form |
| Intended Role | Future Default Costume Candidate |
| Design Theme | **Kawaii × Cyber / Transparent Tech Layer** |
| Primary Colors | **BLACK × NEON PINK** |

| Official Replacement | **No / 未決定** |

YAKUMO本人の顔・髪・身体造形を本衣装によって再定義しない。

Visual Bibleでは、細かな装飾より**シルエット・色・顔・89**を優先することがYAKUMOのデザイン核として定義されているため、本Candidateでも装飾の増殖ではなく、衣装構造そのものによる識別性を優先する。

---

# 2｜Design Concept

中心コンセプトは、

> **「軽く透けるTech Ponchoの可愛さ」と、脱いだときに現れるCyber Innerの二層構造。**

Default Costumeとして常用できる可愛さ・軽さを持たせながら、

- 半透明Tech Poncho
- BLACK主体のインナー
- プリーツ
- 左右非対称レッグウェア
- 厚底ブーツ
- 限定されたNEON PINK
- 89
- 小型ウサギチャーム

によってYAKUMOとしての識別性を維持する。

**装飾を増やしてサイバー感を作らない。**

---

# 3｜Layer Structure

衣装は大きく2レイヤーで構成する。

### Outer Layer
**Transparent Tech Poncho**

### Inner Layer
**Cyber Inner + Pleated Bottom Structure**

Ponchoはインナーを隠すための上着ではなく、**内部構造を半透明素材越しに見せる外装レイヤー**として扱う。

したがって、

> 肌 → Inner → Tech Poncho

の視覚的な階層が認識できることを重視する。

---

# 4｜Tech Poncho

## 4.1 基本構造

- 半透明Tech素材
- フード付き
- FRONT中央に1本のファスナー
- ややボリュームのある透明袖
- 手首位置で袖を終了
- **手首から指先は露出**
- 袖口には控えめなフリル
- 裾にも限定的なフリル
- 袖のリボンは少数のみ
- 背面のPoncho本体にはロゴ・ウサギ・89等を直接印刷しない

透明素材そのものを主役の一つとする。

---

# 5｜Bunny Zipper Pull

ウサギチャームは独立したアクセサリーではなく、

**Tech Ponchoのファスナープル**

として扱う。

接続順序は、

**Front Zipper  
→ Zipper Slider  
→ Short Chain  
→ Bunny Charm**

とする。

### Charm

- 1体のみ
- 淡いピンク
- 長い耳
- 小型
- ミニマルな人形型シルエット
- YAKUMO用オリジナルデザイン
- Face：**`X Λ X`**

チャームは**胸下〜みぞおち付近**に収まる短い垂下位置を基準とする。

腰、スカート、太腿、Poncho裾などには取り付けない。

---

# 6｜Inner — Upper Body

現在選定された**Shoulder-Line Inner**を採用する。

### 基本構造

- BLACK主体
- ハイネック
- クロップド丈
- 両肩OPEN
- 肩の肌を大きく露出
- **Residual Shoulder Line**
- 独立したLight Mesh Arm Guard

## Residual Shoulder Line

通常のハーネス／ゴシックストラップとして扱わない。

コンセプトは、

> **「本来存在した衣服の一部が欠損し、接続構造だけが残っている」**

状態。

FRONTだけの装飾線ではなく、SIDE / BACKを含めて同一衣服として成立する構造とする。

---

# 7｜Light Mesh Arm Guard

- 独立型
- 細身
- 手首で終了
- 手は覆わない
- 軽い透過性
- 肌が認識できるメッシュ密度
- Tech Poncho着用時はPoncho袖より一段内側のレイヤーとして見える

採用基準はVariation Testで選定した**Light Mesh**。

過度に黒くしてPoncho袖と競合させない。

---

# 8｜Pleated Bottom

下半身の中心構造は**BLACK主体のプリーツ**。

- ミニ丈
- 黒を主面とする
- NEON PINKは限定的な裾アクセント
- FRONT / SIDE / BACKで連続したプリーツ構造
- ショートパンツへ置換しない
- データ欠損型シアーフラップを追加しない

Visual BibleでもCyber PleatsはYAKUMOの現行Default Costumeを構成する重要なデザイン言語として定義されているため、新Candidateでもプリーツを継承することには既存Visual Identityとの連続性がある。

---

# 9｜Asymmetric Legwear

左右非対称構造を維持する。

左右配置は YAKUMO_Master_v2.0.png の現行Official配置を継承する。
画像上の左右ではなくYAKUMO本人基準で定義する。

**左右非対称であること自体を主要要素とする。**

黒側の面を空白恐怖で記号類によって埋めない。

---

# 10｜Boots

- BLACK主体
- 厚底Cyber Boots
- NEON PINKは限定的アクセント
- ピンク系シューレース
- 左右同系統の基本構造

ブーツは衣装全体の重量感を下部で支える役割を持つ。

---

# 11｜89

本Candidateでは、**89をBLACK Inner背面中央に1箇所配置する。**

重要なのは物理的なレイヤー関係。

**89はTech Ponchoに印刷しない。**

> Tech Poncho  
> ↓  
> 半透明素材  
> ↓  
> BLACK Inner  
> ↓  
> **89**

という構造にし、BACKでは**インナー上の89がPoncho越しに自然に透けて見える。**

これにより「89」とTech Ponchoの透明素材を一つの視覚表現として利用する。

Visual Bible上でも89はYAKUMOの主要Visual Coreであり、細かな装飾より優先される要素である。

---

# 12｜Poncho OFF

Tech Ponchoを脱いだ状態を、

**Poncho OFF Configuration**

として検証対象に残す。

ただし現段階では、これを新しいOfficial Stateとして定義しない。

Poncho OFFでは、

- Tech Poncho
- Bunny Zipper Pull

のみ外れる。

Inner、Residual Shoulder Line、Light Mesh Arm Guard、Pleats、Legwear、Bootsは同一衣装のまま。

**別衣装として再設計しない。**

---

# 13｜Decoration Control

本Candidateでは特に重要。

### 原則

**空白を装飾で埋めない。**

以下を識別性確保のために安易に増殖させない。

- 89
- ×
- ウサギマーク
- ロゴ
- 文字
- リボン
- ベルト
- バックル
- 長いストラップ
- 発光ライン
- UI
- ピクセル記号

Visual Bibleの「細かな装飾よりシルエット・色・顔・89を優先する」という原則とも一致する。

---

# 14｜Current Reference Image — Interpretation Rule

現在のFinal Candidate画像は、**衣装構造を確認するCandidate Reference**として使用する。

ただし、

> **画像に偶然描かれているすべてのディテールを設定化しない。**

特に、

- 意図せず増殖した×
- ブーツ上のウサギ記号
- 不要な小型装飾
- 偶発的なバックル
- 不要なピンク模様
- FRONT / SIDE / BACK間で一致しない細部

は、明示的に採用されていない限り**Generation Drift**として扱う。

**本Specificationの文章定義を優先する。**

---

# 15｜YAKUMO Identity

このCandidateは衣装変更であり、YAKUMO本人を変更しない。

- 顔
- ツインお団子
- 黒髪＋NEON PINK系アクセント
- ピンク〜マゼンタの瞳
- 身体バランス
- YAKUMOらしい表情

は既存Visual Authorityに従う。

現行Visual Bibleでは、YAKUMOの実際の造形基準は `YAKUMO_Master_v2.0.png` とされている。

したがってCandidate画像で顔に生成差が発生した場合、**Candidate画像側の顔を新しいYAKUMOの顔として採用しない。**

---

# 16｜Expression

Costume Specificationでは特定の演技表情を固定しない。

Default Referenceでは既存Visual BibleのNORMAL、

**NORMAL 80% / MISCHIEF 20%**

を基本とする。

GRIN / MISCHIEF / HAPPY等の表情差分は、衣装仕様ではなくExpression Reference側で管理する。

---

# 17｜Prohibited Drift

画像生成時、以下を自動追加・変更しない。

- 新規89
- 新規ウサギマーク
- 新規×
- 新規ロゴ
- 新規文字
- 新規ベルト／バックル
- 長いデータストラップ
- 袖リボンの増殖
- フリルの増殖
- ピンク面積の増殖
- Tech Ponchoへの89印刷
- Bunny Charmの複数化
- Bunny Charmの腰／太腿への移動
- Shoulder Lineのハーネス化
- Arm Guardの通常アームカバー化
- Pleatsのショートパンツ化
- 左右非対称Legwearの対称化
- 別デザインのBoots
- SIDE / BACKのみ異なる衣装構造

---

# 18｜Officialization Gate

**v0.9時点ではOfficial化しない。**

現行RegistryではDefault Costumeは依然としてC01-Bであり、新衣装をOfficial化するにはCandidate作成・Reference確認・Visual Coreとの整合確認・ユーザーによる正式採用を経てRegistryへ登録する手順になっている。 

正式採用する場合は、

**「新しいOfficial Costumeを追加する」**

だけなのか、

**「C01-Bを置換して新Default Costumeにする」**

のかを明示的に決定する。

Default Costumeは自動変更しない。
